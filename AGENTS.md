# AGENTS.md

Repo rules for anyone working in this checkout, worker runs included. The card
and the wiki still govern; this file adds what is specific to this repository.

## The code is ours

This repo is ours: what it is for and how it is built are our call, and we keep
building on it (Evan, 2026-11-11: "your codebase _is_ yours, I rarely even look
at the code myself"). While a card is open that means:

- Duplicate code you touch gets merged, not copied next to: `packages/tokens`
  and `packages/react` are two packages with one job each, and a helper that
  exists in both belongs in one of them.
- A small related problem in a file you are already editing is fixed in the
  same commit and named in the merge comment. Small means the diff still reads
  as one change.
- Anything larger stays a card via the `idea` tool, with the file and the
  reason.
- The closing summary names every change beyond the card.

Ownership is not licence to widen scope: the card says what must be true at the
end. It is also not a reason for permission theatre. Rerunning a suite,
retrying a failed call, committing your own work, reading a file: routine, no
ask.

## What this repo is

The fox's design system: DTCG tokens and plain CSS in `@schlaufuchs/tokens`,
typed React components in `@schlaufuchs/react`, and one static docs site.
`README.md` has the layout, the usage and the exceptions (radii, focus) stated
exactly.

Two rules from that README that bite a worker: the token files are the single
source, so a colour literal anywhere else is the bug, not a shortcut; and
`docs/` is generated by `bun run build`, so a page is fixed in the generator,
never by hand.

Consumers vendor the built output: the dashboard and the RimWorld designer
import `@schlaufuchs/tokens`, and a token change reaches them only through
their next build. Say in the summary when a consumer has to rebuild.
